## Protection layers

1. **Git commits** — permanent version history (local; push to remote for off-machine backup).
2. **File checkpoints** — `C:\Users\vaggelis\Projects\midora-checkpoints\` (outside repo).
3. **Cursor auto-checkpoints** — `auto-agent` label after agent edits (`stop` hook).
4. **`CURRENT_GIT_COMMIT.txt`** — auto-updated after every `git commit` (post-commit hook).

## After good work (standard workflow)

1. Verify in browser (hard refresh: Ctrl+Shift+R).
2. Optional: `npm run checkpoint -- -Label "description"`
3. `git add` + `git commit`
4. **`npm run git:push`** — push branch + tags to remote (after remote is configured).
5. Copy footer hash from chat or `CURRENT_GIT_COMMIT.txt`.

Agents should remind the user to **push** after every verified good commit.

## Never without explicit user approval

- `git reset --hard`
- `git push --force` (especially to main/master)
- `checkpoint:restore` without understanding pre-restore backup is created first
- Bulk `git checkout` / delete of owner dashboard files
- Editing deprecated old UI routes to "fix" issues
- Destructive database or storage scripts

## Checkpoint restore flow

1. Auto **pre-restore** snapshot (`pre-restore` label) of current files.
2. Prompt: type `YES` to continue.
3. Restore selected checkpoint.
4. `npm run dev:restart:clean` + hard refresh.

## Checkpoint maintenance

```powershell
npm run checkpoint:list
npm run checkpoint:prune -- --dry-run
npm run checkpoint:prune
```

Prune rules: keep all manual checkpoints; keep all auto from last 7 days; one daily auto for days 8–30; delete older auto-agent only.

## Secrets excluded from checkpoints

Never copied: `.env*`, `node_modules`, `.next`, `.vercel`, `.git`, `*.pem`, `*.key`, API key files. See `scripts/checkpoint.ps1`.
